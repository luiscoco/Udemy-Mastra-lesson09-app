    Try, compare, explain.

    Create a shape-valid but inaccurate candidate and observe that validation alone does not detect the false claim. Then restore accuracy by comparing the supplied source.

    01

    Define the output contract

    The study-card schema requires a topic, summary, prerequisites and exactly three key points. The TypeScript result type is inferred from that schema.

    02

    Reject malformed candidates

    Wrong types, missing fields and extra keys produce explicit validation issues. The app does not silently substitute success data.

    03

    Generate structured data

    The live path calls generate with structuredOutput.schema and reads response.object, using the actual Mastra API.

    04

    Validate the returned object

    The same contract checks model output before the application presents typed data. It does not scrape JSON from prose with a regex.

    05

    Separate shape from truth

    A structurally valid but inaccurate summary can still pass. Compare the study card with the supplied passage as a separate review.

    06

    Review consumers when the schema changes

    Field names and constraints affect the UI and downstream logic. Regenerate source-linked pages and rerun tests after changing the contract.
